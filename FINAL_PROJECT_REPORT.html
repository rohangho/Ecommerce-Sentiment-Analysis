1. Executive Summary & Project Objectives

This comprehensive technical report outlines the rigorous development, evaluation, and end-to-end deployment of a production-ready Machine Learning ecosystem. Mapped against a large-scale e-commerce textual dataset consisting of thousands of Amazon consumer reviews for electronics and devices, this project moves far beyond standard natural language processing (NLP) constraints.

Historically, commercial sentiment analyzers fail when faced with high-variance class imbalance, colloquial slang, and nuanced multi-feature subtexts (e.g., distinguishing between a "good battery" and a "terrible screen" inside the same review block). Our methodology bridged these algorithmic gaps via a highly resilient, dual-layered transformer architecture completely containerized inside a Docker-backed Continuous Learning loop.

Primary Objectives Achieved

  • Multi-Model Scientific Benchmarking: Engineered a unified classification arena testing 7 distinct ML and DL models head-to-head utilizing K-Fold cross-validation over sparse datasets.
  • Structural Mitigation of Class Disproportionality: Systematically countered a 93% extreme positive-review skew using programmatic compute_class_weight algorithms.
  • Aspect Distillation: Bypassed unsupervised noise generated by demographic variance by creating a Hybrid JSON-Keyword-to-BERTopic extraction mapping schema.
  • Ops / Deployment: Fully containerized operations using docker-compose implementing a real-time web UI synced with a non-blocking background watchdog process for zero-downtime hot-reloading dataset adjustments.

3.2 Why DeBERTa Won & Hyperparameter Tuning Phase

The core advantage of DeBERTa (Decoding-enhanced BERT with Disentangled Attention) is its internal mechanism mapping spatial matrices. Unlike BERT which meshes contents and word positional arrays into a single vector, DeBERTa utilizes disentangled attention. This allows the model to process "The battery is bad but screen is good" by mathematically separating the exact spatial relationship mapping the word 'bad' directly against 'battery' with higher contextual proximity.

We achieved maximum stabilization for DeBERTa utilizing these explicitly engineered hyperparameters embedded in src/models/sentiment_analysis_DeBERTa.py:

  • Max Vocabulary Sequence Length: 256 Context Window
  • Batch Size Constraint: 4 (Safeguarding Apple GPU / Server RAM threshold clipping)
  • Learning Rate Decay: 2e-5 utilizing create_optimizer scaling.
  • Warmup Ratio: 0.12 (Forcing the learning gradient to softly curve 12% into the total step count avoiding sudden gradient shattering).
  • Weight Decay: 0.02 (L2 Regularization preventing strict overfitting on the positive majority).
  • Training Epochs: 3 (yielding maximum convergence before validation loss diverged).

4. Specialized Advanced Engineering Implementations

4.1 Solving Slang Erosion via Confidence-Gated Multi-Threading

A staggering challenge observed during validation was the model's inability to comprehend aggressive colloquial jargon. Words like "sucks" had roughly zero appearances in the formal Amazon documentation matrix. Thus, a review stating "The sound sucks" yielded a catastrophic 'Neutral' flag.

We engineered a structural threshold logic: We check the output SoftMax distribution tensors yielded by DeBERTa. If DeBERTa expresses inference confidence dropping below 65% (0.65 threshold), the pipeline flags the request as erratic. The incoming string is immediately intercepted and shunted backward into a localized Cardiff RoBERTa Fallback framework. Pre-trained extensively against a raw 124M block of Twitter semantics, Cardiff correctly processes unseen structural slang resulting in a stable return. This bridges structural business logic cleanly over standard AI inaccuracies.

4.2 Dual-Layered Aspect Tagging (Handling Demographic Drift)

While extracting sentiment acts as an X-axis, the business logic Y-axis requires assigning exactly *what* structural component triggered the sentiment. This required shifting to unsupervised Natural Language algorithms, specifically BERTopic.

Phase 1: The Raw BERTopic Hallucination Problem

Initially deploying raw BERTopic sequentially utilizing all-MiniLM-L6-v2 Sentence-Transformers to generate structural embeddings, reducing dimensions via UMAP, and clustering coordinates via HDBSCAN, resulted in a severe dataset complication. Amazon product reviews heavily interleave product functionality with demographics ("I bought this beautiful tablet as a gift for my teenage daughter"). Instead of isolating features like [Screen, Battery], the baseline c-TF-IDF algorithm clustered embeddings by demographics, generating mathematically sound but completely unusable topic tags like "teenage_daughter_gift_beautifully".

Phase 2: Guided Semi-Supervised Overrides

To cure the demographic drift without needing thousands of manually labeled examples, we drastically re-architected train_bertopic.py using advanced Semi-Supervised Guided implementations:

  • Custom CountVectorizer & Stopword Filtration: Hardcoded an aggressive physical filter (`EXTRA_STOPWORDS`) mathematically stripping words like "grandson", "birthday", and "beautifully" natively from the Tokenizer before c-TF-IDF creates the label matrix.
  • KeyBERT & Maximal Marginal Relevance (MMR): Overrode the standard labeling output by stacking KeyBERTInspired() models mapping local contextual relevance alongside MaximalMarginalRelevance(diversity=0.3) to forcefully enforce diverse word sampling for cluster definitions.
  • Seed-Guided UMAP Injection: Leveraged seed_topic_list parameters passing defined product matrices directly into the UMAP dimensionality phase, literally establishing gravitational anchors that pull loosely related embeddings toward relevant hardware groupings.

Phase 3: Real-Time Dynamic Keyword Harvesting

Because BERTopic forces a 1-to-1 singular mapping per review, it failed when a text contained multiple elements ("RAM is good but Storage is bad"). We culminated the pipeline by building a JSON Multi-Aspect Dictionary Engine loaded natively into the Web App. The web scanner regex-parsers the incoming text against seed_topics.json, pulling dynamic overlapping array combinations (Output: ["RAM", "Storage"]), returning BERTopic only as a generalized safety fallback for categorically unseen texts! This multi-vector approach fundamentally guarantees structured UI plotting.

5. Key Technical Challenge Post-Mortem

Systemic Failure Detected Mathematical / Functional Recovery Engineered
Severe Class Imbalance (Dataset compromised measuring 93% majority) Disregarded accuracy and instituted balanced class weights manipulating the Keras SparseCategoricalCrossentropy logic to massively penalize incorrect predictions on minority subsets safely.
Host PyTorch Loading CVE Vulnerabilities PyTorch Hub recently locked down from_pt=True serialization functions limiting standard execution. Rewrote integration protocols natively simulating and persisting metadata structures decoupling Docker configurations from external PyTorch patches avoiding crashing cycles.
Apple CPU Silicon Thread Clashing Discovered fatal crashes caused by OpenMP overlapping multiple logical cores recursively during HDBSCAN phase. Hard-capped parameters utilizing OMP_NUM_THREADS=1 resolving hardware freezes universally across host machines.
Massive Re-Download Blocking Deploying ML APIs typically crashes UI when reloading multi-GB structures via REST. Caching methodologies using persistent Docker volumes directly mounting /deploy_models allowed 0-second re-mounts loading safe .safetensors dynamically.
